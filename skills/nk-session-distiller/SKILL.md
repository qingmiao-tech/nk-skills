# nk-session-distiller（会话沉淀助手）

## 目标

把长会话从“聊天上下文”转成可复用资产：

- 新会话能快速接上任务。
- 跨 Codex、Claude Code、Hermes、飞书时有共同上下文。
- 值得复用的方法、踩坑、目录契约和命令沉淀到 Obsidian。
- 不值得沉淀的会话只做轻量 handoff 或直接跳过。

## 工作流

1. 明确输入来源：当前对话、Codex JSONL、Claude Code 记录、Hermes/飞书文本，或用户指定的文件路径。
2. 如果输入是 Codex JSONL，先运行辅助脚本生成证据包：

```powershell
python ".codex/skills/nk-session-distiller/scripts/extract_codex_session.py" --input "C:/Users/Administrator/.codex/sessions/YYYY/MM/DD/rollout-xxx.jsonl" --output "10.Hermes协同/会话记录/_tmp/session-digest.md"
```

3. 阅读证据包或会话正文，先做“主题拆分判断”。
4. 对每个候选主题分别按“是否值得沉淀”评分。
5. 根据主题数量和评分，决定输出一篇、拆成多篇，还是只生成轻量 handoff。
6. 写入 Markdown 文档，并在回复里给出路径、判断结果和后续使用方式。

## 主题拆分判断

长会话不要默认压成一篇文档。先按任务目标、产物、工具链和后续用途拆出候选主题，再决定是否合并。

### 候选主题识别

出现以下任意情况时，先列为独立候选主题：

- 任务目标不同：例如打卡生成、文章改稿、技能创建、工作流复盘、Git 提交。
- 产物不同：例如公众号草稿、Obsidian 复盘、技能文件、项目 handoff、打卡文件。
- 工具链不同：例如飞书/Coze、Codex/Claude Code、Obsidian、Git、图像生成。
- 后续读者不同：例如公开教程、内部复盘、新会话接手、课程素材。
- 决策边界不同：例如平台分发策略、模型切换策略、技能同步策略。

### 拆分规则

优先拆成多篇的情况：

- 至少 2 个候选主题评分达到 7 分及以上。
- 主题之间后续用途不同，放在一篇里会影响检索和复用。
- 用户明确指出“内容比较多”“这个标题太窄”“按主题拆分”等。
- 同一会话里既有方法论沉淀，又有具体项目 handoff 或公开稿素材。

只保留一篇的情况：

- 只有 1 个主题评分达到 7 分及以上，其他内容只是背景或过程证据。
- 多个候选主题都服务于同一个核心产物，拆开后反而割裂。
- 用户明确只要求沉淀某一个指定主题。
- 其他主题评分低于 4 分，不值得单独成文。

需要生成索引的情况：

- 最终输出 2 篇及以上正式文档。
- 长会话跨越多个阶段，新会话需要先理解全局地图。
- 用户可能后续按不同任务继续接入。

索引文档命名建议：

```text
YYYY年M月D日-长会话主题拆分索引.md
```

索引只写主题地图、拆分理由、阅读顺序和文档链接，不承载详细复盘。

## 沉淀评分

每项 0 到 2 分，总分 10 分。若会话被拆成多个候选主题，应分别评分，不要只给整轮会话一个总分：

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 复用价值 | 一次性闲聊 | 局部可参考 | 后续同类任务会反复用 |
| 决策密度 | 没有明确决策 | 有零散选择 | 有关键架构、流程或边界决策 |
| 证据质量 | 缺少路径和命令 | 有部分线索 | 有文件、命令、错误、验证结果 |
| 跨会话必要性 | 不影响继续 | 有帮助 | 新会话必须读取才能少走弯路 |
| 知识库适配 | 不适合成文 | 可做 handoff | 可沉淀为正式知识库文档 |

判断规则：

- 0 到 3 分：不沉淀，只简短说明原因。
- 4 到 6 分：生成轻量 handoff，优先放项目内 `docs/ai-handoff/` 或 `10.Hermes协同/任务记录/`。
- 7 到 10 分：生成正式知识库文档。
- 同一主题既有任务交接又有方法论价值时，输出两份：项目 handoff + Obsidian 复盘。

## 目标目录

优先按内容性质选择：

| 内容类型 | 目标目录 |
| --- | --- |
| AI 工作台、Codex、Claude Code、Hermes、飞书、Obsidian 协同复盘 | `09.经验沉淀/AI工作流复盘/` |
| 可复用项目案例、商业规划、工程项目复盘 | `09.经验沉淀/项目案例库/` |
| Hermes 或飞书线程原文归档 | `10.Hermes协同/会话记录/YYYY/` |
| Agent 执行结果、状态、待办 | `10.Hermes协同/任务记录/` 或 `10.Hermes协同/Agent工作台/` |
| 代码项目继续开发 handoff | 当前项目的 `docs/ai-handoff/`，没有则建议创建 |
| 公众号或公开内容草稿 | `07.发布文案/2026年/草稿/`，但只有用户明确要写公开稿时才走这里 |

文件名格式：

```text
YYYY年M月D日-主题关键词.md
```

## 正式知识库文档模板

```markdown
# 标题

## 文档定位

说明这份文档是内部复盘、项目 handoff、课程素材、还是原始会话归档。

## 背景

这次会话解决什么问题，为什么值得沉淀。

## 关键结论

- 结论 1
- 结论 2
- 结论 3

## 过程复盘

按时间或阶段梳理关键动作、判断和转折。

## 关键文件与命令

```text
path/or/command
```

## 踩坑与边界

- 问题：现象
  处理：做法

## 后续接手提示

新会话继续工作前应该先读哪些文件、执行哪些验证、避免哪些动作。

## 原始会话索引

- session_id:
- rollout_path:
- 来源:
```

## 写作要求

- 用中文简体。
- 不要把完整会话原文塞进复盘文档，只保留关键证据和可复用判断。
- 涉及密钥、token、cookie、私有 URL、手机号、身份证、生产库连接串时必须脱敏。
- 明确区分“已验证事实”和“基于会话推断”。
- 如果只是创建文档，不要自动提交、推送或改分支。
- 先读现有目录和 README，再写入新文档。

## 辅助脚本

`scripts/extract_codex_session.py` 只负责抽取证据包，不负责最终判断。最终是否沉淀、放哪、怎么写，由本技能根据评分规则决定。
